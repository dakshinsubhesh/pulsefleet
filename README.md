## Migration Verification

Successfully applied the migration using:
```bash
alembic upgrade head
```

Current migration:
`b6187da16e99 (head)`

Ran a full `upgrade → downgrade → upgrade` cycle against a live database to confirm the migration is reversible. This surfaced a real issue: Alembic's autogenerated `downgrade()` does not drop PostgreSQL's native ENUM types (only the tables), which caused a `DuplicateObjectError` on the next `upgrade`. Fixed by explicitly dropping each ENUM type in `downgrade()`. Re-verified with multiple upgrade/downgrade cycles — clean with no leftover objects.

The database connection was also verified independently using the async SQLAlchemy engine (a direct query executed successfully via `AsyncSessionLocal`).
