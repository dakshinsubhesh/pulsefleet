# PulseFleet — API Design (Day 2)

## 1. Entities and relationships

```
Driver  1 ──── * Shipment * ──── 1  Vehicle
                    │
                    │ 1
                    │
                    ▼ 1
                  Route
                    │
                    │ (risk signals feed prediction)
                    ▼
              Alert * (many per Shipment)
```

- **Driver** — a person who can be assigned to shipments. `1 Driver → * Shipments`.
- **Vehicle** — a fleet asset. `1 Vehicle → * Shipments` (over time, not concurrently).
- **Shipment** — the core entity: one delivery job, optionally linked to a Driver and Vehicle.
- **Route** — 1:1 with Shipment. Holds distance/duration/risk flags that the prediction logic reads.
- **Alert** — 0..* per Shipment. Generated by the system (not user-created) when risk rules fire; can be resolved by a user.

## 2. Request/response contracts

Defined in `app/schemas.py` using the Create / Update / Response split:

| Entity   | Create schema     | Update schema     | Response schema    |
|----------|--------------------|--------------------|----------------------|
| Driver   | `DriverCreate`      | `DriverUpdate`      | `DriverResponse`      |
| Vehicle  | `VehicleCreate`     | `VehicleUpdate`     | `VehicleResponse`     |
| Shipment | `ShipmentCreate` (nests `RouteCreate`) | `ShipmentUpdate` | `ShipmentResponse` (nests `RouteResponse`) |
| Alert    | — (system-generated) | `AlertResolveRequest` | `AlertResponse`     |

Shared error contract: `ErrorResponse { detail: str, error_code: str | None }` — returned on every 4xx/5xx.

## 3. REST endpoint plan

### Drivers

| Method | Path              | Body              | Success            | Error cases |
|--------|--------------------|--------------------|----------------------|--------------|
| POST   | `/drivers`          | `DriverCreate`      | 201 `DriverResponse` | 422 validation |
| GET    | `/drivers`          | —                    | 200 `list[DriverResponse]` | — |
| GET    | `/drivers/{id}`     | —                    | 200 `DriverResponse` | 404 not found |
| PATCH  | `/drivers/{id}`     | `DriverUpdate`       | 200 `DriverResponse` | 404 not found, 422 validation |
| DELETE | `/drivers/{id}`     | —                    | 204                   | 404 not found, 409 conflict (has active shipments) |

### Vehicles

| Method | Path               | Body               | Success              | Error cases |
|--------|---------------------|----------------------|------------------------|--------------|
| POST   | `/vehicles`          | `VehicleCreate`       | 201 `VehicleResponse`  | 422 validation |
| GET    | `/vehicles`          | —                     | 200 `list[VehicleResponse]` | — |
| GET    | `/vehicles/{id}`     | —                     | 200 `VehicleResponse`  | 404 not found |
| PATCH  | `/vehicles/{id}`     | `VehicleUpdate`       | 200 `VehicleResponse`  | 404 not found, 422 validation |
| DELETE | `/vehicles/{id}`     | —                     | 204                    | 404 not found, 409 conflict (in use) |

### Shipments (core resource)

| Method | Path                       | Body               | Success                 | Error cases |
|--------|------------------------------|----------------------|----------------------------|--------------|
| POST   | `/shipments`                 | `ShipmentCreate`      | 201 `ShipmentResponse`     | 422 validation, 404 driver/vehicle not found |
| GET    | `/shipments`                 | — (query filters, see §4) | 200 `list[ShipmentResponse]` | 422 bad filter params |
| GET    | `/shipments/{id}`            | —                     | 200 `ShipmentResponse`     | 404 not found |
| PATCH  | `/shipments/{id}`            | `ShipmentUpdate`      | 200 `ShipmentResponse`     | 404 not found, 422 validation, 409 invalid status transition |
| DELETE | `/shipments/{id}`            | —                     | 204                        | 404 not found, 409 conflict (already in transit) |

### Alerts (predictive exceptions)

| Method | Path                                | Body                  | Success                 | Error cases |
|--------|---------------------------------------|-------------------------|----------------------------|--------------|
| GET    | `/alerts`                              | — (filters: severity, resolved, shipment_id) | 200 `list[AlertResponse]` | 422 bad filter params |
| GET    | `/alerts/{id}`                         | —                        | 200 `AlertResponse`        | 404 not found |
| POST   | `/shipments/{id}/evaluate`             | —                        | 200 `list[AlertResponse]` (may be empty) | 404 shipment not found |
| PATCH  | `/alerts/{id}/resolve`                 | `AlertResolveRequest`    | 200 `AlertResponse`        | 404 not found, 409 already resolved |

`POST /shipments/{id}/evaluate` is the prediction trigger: runs the rule-based scoring (weather flag, distance vs. time budget, driver load) against the shipment + its route, creates any new `Alert` rows, and returns the current alert set. This is the endpoint Day 9–10 (rules engine + service integration) plugs into.

## 4. Query filters (Shipments & Alerts list endpoints)

- `GET /shipments?status=in_transit&driver_id=3&priority=3`
- `GET /alerts?severity=high&resolved=false&shipment_id=12`

Invalid enum values or non-numeric IDs → `422` with `ErrorResponse`.

## 5. Standard error responses across all endpoints

| Code | Meaning                          |
|------|-------------------------------------|
| 404  | Resource not found                    |
| 409  | Conflict — state transition or FK constraint not allowed |
| 422  | Validation error (FastAPI/Pydantic default) |
| 500  | Unhandled server error               |

All non-2xx responses conform to `ErrorResponse`.
